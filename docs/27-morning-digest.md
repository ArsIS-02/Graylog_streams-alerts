# 27. Утренний дайджест: пульсы и алерты за сутки одним письмом

Алерты прилетают по одному — к утру в почте куча писем, а общая картина «что с лабой за ночь» собирается только глазами. Теперь в 08:47 приходит один дайджест: пульсы всех четырёх инструментов (сколько, когда последний, какие счётчики нёс) и сводка срабатываний всех алертов за сутки, сгруппированная по правилам. Почтовых кредов в скрипте нет — письмо шлёт сам Graylog.

> **Статус проверки.** Сквозной прогон (ноябрь 2026): скрипт отправил GELF-сообщение `dg_event=digest` (1491 символ), правило сработало через ~20 секунд, поля `dg_status`/`dg_alerts_total` подтянулись в событие, письмо ушло без ошибок (system notifications: 0). Таймер `morning-digest.timer` активен, следующий запуск — 08:47 YEKT, `Persistent=true` (пропущенный запуск при выключенной машине догонится). Каталог HomeWiki синхронизирован — 246 правил, у дайджеста есть runbook-страница.

## Как устроено

```
redos-server                          Graylog (там же)                почта
┌─────────────────────┐   GELF UDP    ┌──────────────────────────┐
│ morning-digest.timer│  127.0.0.1    │ DIGEST - Утренний        │  notification   ┌──────────┐
│  └ morning-digest.py│ ────────────► │  дайджест экосистемы     │ ──────────────► │ 📨 письмо │
│    (08:47 YEKT)     │  dg_event=    │  (aggregation, 60/60 с)  │  Mail.ru Daily  └──────────┘
└─────────────────────┘  digest       └──────────────────────────┘  Digest
```

Три новых объекта, все в репозитории:

- **`graylog/morning-digest.py`** — скрипт ([глава целиком про него](#скрипт)): забирает из Graylog API пульсы и алерты за 24 часа, собирает текст, шлёт одним GELF-сообщением на вход «Homelab tools» (`127.0.0.1:12206`). `--dry-run` печатает текст без отправки;
- **правило «DIGEST - Утренний дайджест экосистемы»** — паттерн мгновенного алерта (глава 21): запрос `dg_event:digest` по всем потокам, окно/период 60 с, без series и условия — срабатывает на само сообщение, `backlog_size: 1` кладёт текст дайджеста в письмо. Экспорт — `graylog/homelab-tools-event-definitions.json`;
- **уведомление «Mail.ru Daily Digest»** — клон «Mail.ru Alert Homelab tools» с темой `📨 Утренний дайджест экосистемы — ${event.fields.dg_status}` (статус проброшен через `field_spec` из поля сообщения). Экспорт — `graylog/notifications.json`.

Письмо — тот же тёмный HTML-шаблон с кнопками «Открыть в Graylog» и «Разбор в HomeWiki» (ведёт на страницу правила дайджеста), текст дайджеста — в блоке исходного сообщения моноширинным шрифтом, на телефоне читается.

## Скрипт

Логика (`graylog/morning-digest.py`, ~150 строк, зависимостей нет — только stdlib):

1. **Пульсы**: для каждого инструмента (`hr_/hd_/zs_/tl_event:heartbeat`) — универсальный поиск за 24 ч. Живость определяется по **свежести последнего пульса** (старше 2 часов — ❌ «молчит»), а не по количеству: счётчик за сутки показан информационно («пропуски за сутки (5/20+)»), потому что первые дни после внедрения heartbeat количество ещё не накопилось и по нему всё выглядело мёртвым.
2. **Алерты**: все события потока All events за 24 ч, группировка по правилу на клиенте (terms-агрегация по `message` в Graylog падает — глава 26). Из текста события отрезается хвост ` - count()=1.0` (regex `\s*[-:]\s*count\(\)=[\d.]+$`), иначе каждое срабатывание считалось бы отдельным правилом. Групповой ключ (хост) в заголовке сохраняется — «chmod: redosrp16» и «chmod: redos-server» видны раздельно, это полезно.
3. **Отправка**: GELF UDP с чанкованием (тот же формат, что в TrafficLens): текст дайджеста уезжает в `short_message` — Graylog кладёт его в поле `message`, а шаблон письма печатает `${m.message}` из backlog. Плюс поля `dg_event=digest`, `dg_status`, `dg_alerts_total`, `dg_silent_tools`.

## Установка на сервере

```bash
mkdir -p ~/graylog-digest && cp morning-digest.py ~/graylog-digest/
# ~/.config/systemd/user/morning-digest.service — oneshot, ExecStart=python3 %h/graylog-digest/morning-digest.py
# ~/.config/systemd/user/morning-digest.timer   — OnCalendar=*-*-* 08:47:00, Persistent=true
systemctl --user daemon-reload && systemctl --user enable --now morning-digest.timer
systemctl --user start morning-digest.service   # сквозной тест: письмо придёт через ~1–2 минуты
```

Время 08:47 выбрано не круглое специально — круглые минуты (:00, :30) у cron-задач и так перегружены. Время локальное серверное (YEKT). Конфигурация — переменные окружения `DIGEST_GRAYLOG_URL/USER/PASSWORD`, `DIGEST_GELF_HOST/PORT`, значения по умолчанию соответствуют лаборатории.

## Грабля: JSON-обёртки при экспорте

При автоматическом дописывании уведомления в `notifications.json` скрипт развернул `{"generated": …, "notifications": […]}` в плоский список — и чуть не закоммитил файл без обёртки. Правило из этой истории: после любого программного редактирования экспортов — `git diff --stat` глазами, особенно когда «всего-то добавили один элемент». Поймано до коммита, обёртка восстановлена из `git show HEAD:`.
