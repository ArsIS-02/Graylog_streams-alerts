# Проверка детектов

> Набор безопасных сценариев, которые на тестовой машине создают события, похожие на следы атак, чтобы убедиться: правила из [каталога детектов](14-detections.md) срабатывают и письма доходят. Проверок: **121**, правил каталога покрыто: **164** из 218.

Файлы лежат в каталоге [`detection-tests`](../detection-tests). Скрипты ничего не ломают: тестовые учётные записи, файлы, службы и ключи реестра создаются с префиксом `DT_` или `dt_test` и удаляются в конце, а опасные техники имитируются безвредной командной строкой (`cmd /c rem ...`, `bash -c 'true # ...'`). Запускайте их только в лаборатории.

## Как это работает

1. Раннер выполняет выбранные проверки по очереди и пишет в отчёт время начала и конца каждой.
2. После каждой проверки он делает паузу (по умолчанию 5 секунд) и в конце удаляет всё созданное.
3. Вы открываете Graylog (`Alerts → Events`) и сверяете по отчёту, какие алерты пришли. Колонка `seen_in_graylog` в отчёте пустая: заполните её сами.

Правило срабатывает с задержкой: расчёт идёт раз в 5 минут, плюс доставка письма. Ожидайте до 10 минут после конца прогона.

**Важно про повторы.** У большинства правил есть период тишины (чаще всего час): пока он не прошёл, повторное событие нового алерта не даёт. Если прогон уже срабатывал недавно, а алерта нет, это не обязательно ошибка. Для повторной проверки подождите час или временно уменьшите период тишины у правила.

## Запуск

Каждый раннер умеет одно и то же:

| Действие | Windows (PowerShell) | Linux, macOS (bash) | FreeIPA (Python) |
|---|---|---|---|
| Список проверок | `-List` | `--list` | `--list` |
| Показать, что будет сделано | `-DryRun` | `--dry-run` | `--dry-run` |
| Выбрать проверки | `-Id WIN-01,WIN-05` | `--id LNX-01,LNX-05` | `--id IPA-01,IPA-06` |
| Все проверки | `-All` | `--all` | `--all` |
| Без вопросов | `-Force` | `--yes` | `--yes` |
| Пауза между проверками | `-PauseSec 5` | `--pause 5` | `--pause 5` |
| Путь отчёта | `-Report путь.csv` | `--report путь.csv` | `--report путь.csv` |

Без параметров раннер показывает список и просит выбрать проверки.

```powershell
# Windows: на контроллере домена или рабочей станции, от администратора
.\Invoke-DetectionTests.ps1 -List
.\Invoke-DetectionTests.ps1 -Id WIN-01,WIN-09 -DryRun
.\Invoke-DetectionTests.ps1 -All -Target dc01.example.test
```

```bash
# Linux: на хосте с auditd, от root
sudo ./detection-tests.sh --list
sudo ./detection-tests.sh --id LNX-01,LNX-05
# macOS: из пользовательской сессии администратора
./detection-tests.sh --all
# FreeIPA: на сервере или клиенте IPA
kinit admin
python3 ipa_detection_tests.py --all
```

## Как сверять результат

Раннер печатает в конце сводку: окно времени, список ожидаемых алертов по каждой проверке и путь к CSV-отчёту. В Graylog откройте `Alerts → Events`, задайте то же окно времени и сверьте названия. Если алерта нет, идите по цепочке: дошёл ли лог в поток (поиск по потоку), подходит ли поле под запрос правила, не действует ли период тишины.

## Как добавить проверку

1. Опишите её в [`tests_def.py`](../detection-tests/tests_def.py): id, название, подстроки названий правил из каталога, риск, условия.
2. Напишите реализацию в раннере платформы: функция `Test-WIN34`, `t_LNX_31`, `t_MAC_30` или `test_IPA_12` (по id). Всё созданное регистрируйте для удаления.
3. Выполните `python3 build_tests.py`: скрипт проверит правила по `catalog.csv`, наличие функции, обновит описания в раннерах и эту страницу.
4. Прогоните проверку у себя и убедитесь, что алерт приходит.
