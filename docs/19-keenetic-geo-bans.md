# 19. Keenetic: блокировки внешних адресов на карте мира

Роутер Keenetic сам банит адреса, которые подбирают пароль к его веб-интерфейсу, и пишет об этом в системный журнал. Эта глава собирает такие события в дашборд: адреса, страны, города, динамика и точки на карте мира.

> **Что здесь не покрыто.** Дашборд показывает только блокировки доступа к управлению роутером (`Netfilter::Lockout::Manager`). Отброшенные пакеты при обычном сканировании портов Keenetic в системный журнал по умолчанию не пишет, поэтому в Graylog их нет. Это проверено по логам лаборатории за 7 дней: в них есть баны и снятие банов с IP, но нет записей о drop/reject межсетевого экрана. Чтобы видеть сканирование портов, нужно отдельно включать логирование отбрасываемых пакетов (на роутере или на хосте за ним).

> **Статус проверки.** Регулярное выражение правила проверено на реальных строках лога. Дашборд прогнан через `importDashboards(..., {dryRun: true})`. На живом Graylog 7.2.1 правило, GeoIP и виджет карты по этой инструкции ещё не запускались: имена полей геолокации и тип поля для карты проверьте по шагу 5.

## Как это устроено

```
Keenetic ──syslog──▶ Graylog (поток «Syslog Logs»)
                      │
                      ├─ pipeline-правило «keenetic: lockout ban IP»:
                      │     kn_ban_ip, kn_lockout_action (ban/unban), kn_lockout_service
                      │
                      ├─ Geo-Location Processor (MaxMind GeoLite2 City):
                      │     по kn_ban_ip добавляет координаты, страну, город
                      │
                      └─ дашборд «Keenetic: блокировки внешних адресов»
```

Строка в журнале выглядит так:

```
Keenetic-7625 ndm: Netfilter::Lockout::Manager: "Http": ban remote host 68.183.9.16 for 15 minutes.
Keenetic-7625 ndm: Netfilter::Lockout::Manager: "Http": unban remote host 68.183.9.16.
```

## Шаг 1. Логи роутера в Graylog

Если роутер уже шлёт syslog в Graylog (поток `Syslog Logs`), этот шаг пропустите. Иначе в веб-интерфейсе роутера: «Диагностика → Системный журнал → Использовать Syslog», адрес сервера Graylog. Или в CLI роутера:

```
system log server 192.168.1.137:1514
```

Роутер шлёт формат BSD syslog по UDP, по умолчанию на порт 514. Graylog под непривилегированным пользователем порт 514 не слушает, поэтому создайте input Syslog UDP на порту 1514 и укажите его в адресе сервера.

## Шаг 2. Pipeline-правило

Файл [`graylog/pipelines/rules/keenetic-lockout-ban-ip.rule`](../graylog/pipelines/rules/keenetic-lockout-ban-ip.rule). Правило достаёт из текста три поля:

| Поле | Пример | Что это |
|---|---|---|
| `kn_ban_ip` | `68.183.9.16` | адрес, который забанил или разбанил роутер |
| `kn_lockout_action` | `ban` / `unban` | что произошло |
| `kn_lockout_service` | `Http` | какую службу роутера защищает блокировка |

Загрузка правила описана в [`graylog/pipelines/README.md`](../graylog/pipelines/README.md): `import-rules.js` с содержимым `rules.json` в консоли браузера. Затем подключите правило вручную: **System → Pipelines → ваш pipeline разбора Keenetic → стадия → Add rule**. Поставьте его в стадию раньше или вместе с правилами Keenetic, главное, чтобы оно выполнялось до Geo-Location Processor (шаг 3 это обеспечивает порядком процессоров).

## Шаг 3. Геолокация

В Graylog есть встроенный Geo-Location Processor. Он берёт из сообщения поля, содержащие IP-адрес, и добавляет к ним координаты, страну и город.

1. Зарегистрируйтесь на сайте MaxMind и скачайте бесплатную базу **GeoLite2 City** (файл `GeoLite2-City.mmdb`). Лицензия GeoLite2 не позволяет выкладывать базу в публичный репозиторий, поэтому в этом репозитории её нет.
2. Положите файл на хост Graylog, например в `/etc/graylog/server/GeoLite2-City.mmdb`, владелец `graylog`, права `0644`. При включённом SELinux проверьте метку командой `ls -Z`.
3. **System → Configurations → Geo-Location Processor**: включите процессор, тип базы MaxMind, путь к файлу, интервал обновления. Базу нужно периодически обновлять (MaxMind выпускает её несколько раз в неделю), удобно сделать таймер systemd.
4. На той же странице **Message Processors Configuration** процессор «Geo-Location Processor» должен стоять **после** «Pipeline Processor». Тогда `kn_ban_ip` уже будет создан правилом, когда дойдёт очередь до геолокации.

Для частных адресов (192.168.x.x и подобных) GeoIP ничего не добавит. Для бана адреса из локальной сети точка на карте не появится, это нормально.

## Шаг 4. Дашборд

Дашборд `🛡️ Keenetic: блокировки внешних адресов` лежит в [`graylog/dashboards-spec.json`](../graylog/dashboards-spec.json). Он подключается так же, как остальные: `import-dashboards.js` в консоли браузера (подробности в [главе 7](07-dashboards.md)). Сначала пробный запуск:

```js
await importDashboards(SPEC, {dryRun: true})
```

Если нужен только этот дашборд, отфильтруйте массив: `SPEC.filter(d => d.title.includes('блокировки внешних'))`. Потоки находятся по названию, нужен поток `Syslog Logs`.

На дашборде одиннадцать виджетов: четыре счётчика (баны, уникальные адреса, страны, снятые баны), карта мира, график по времени, топ стран, топ городов, топ адресов со страной, круговая диаграмма по службам роутера и таблица последних блокировок.

## Шаг 5. Проверка

1. Отправьте на input тестовое сообщение с текстом из примера выше (например, через GELF или `logger`), либо дождитесь реального бана.
2. Откройте сообщение в поиске и убедитесь, что есть поля `kn_ban_ip`, `kn_lockout_action`, `kn_lockout_service`.
3. Проверьте поля геолокации. Ожидаются поля вида `kn_ban_ip_geolocation` (координаты `"широта,долгота"`), `kn_ban_ip_country_code`, `kn_ban_ip_city_name`. Именно эти имена использует дашборд. Если у вас они называются иначе, замените их в виджетах (в spec это `kn_ban_ip_geolocation`, `kn_ban_ip_country_code`, `kn_ban_ip_city_name`).
4. Для виджета «World Map» поле с координатами в индексе должно иметь тип `geo-point`. Если карта пустая, а поле есть, откройте **System → Indices → ваш index set → Field Type Mappings** и задайте для поля тип geo-point, затем сделайте ротацию индекса (**Maintenance → Rotate active write index**). Старые сообщения останутся с прежним типом.
5. Если карта не появилась при импорте или не рисуется, добавьте виджет вручную: Add widget → Aggregation → World Map, поле `kn_ban_ip_geolocation`, метрика `count()`.

## Что можно добавить дальше

- Алерт «массовый перебор»: больше N разных адресов забанено за час (определение события по агрегации `card(kn_ban_ip)`).
- Включить логирование отброшенных пакетов, чтобы на этой же карте видеть сканирование портов, а не только подбор пароля к веб-интерфейсу.
- Список «известных сканеров» в Lookup Table и пометка повторяющихся адресов.
- Закрыть доступ к управлению роутером из интернета, если он не нужен: баны тогда станут редкостью.
