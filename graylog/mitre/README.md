# Карта MITRE ATT&CK для алертов

Каждое определение события Graylog привязано к технике MITRE ATT&CK v20 (Enterprise). Привязка
записана в сами события, по ней строятся дашборд, слой для ATT&CK Navigator и страница с матрицей.

В ATT&CK v20 матрицу перестроили: появились тактики `Stealth` (TA0005) и `Defense Impairment`
(TA0112), техник `T1562.*` и `T1070.001/.002` больше нет, вместо них `T1685.*` и `T1686.*`.
Идентификаторы в таблице уже новые. Справочник для проверки лежит в `attack-ref.json`.

## Что внутри

| Файл | Зачем |
|---|---|
| `attack-mapping.md` | Таблица «определение → техники», тактика, уверенность, пометка. Читать глазами |
| `attack-mapping.json` | То же в виде данных |
| `build_mapping.py` | Список соответствий (`rows`) и проверка идентификаторов по `attack-ref.json`. Правите здесь, запускаете `python3 build_mapping.py` |
| `attack-ref.json` | Сжатый справочник ATT&CK v20: тактики и техники |
| `mitre-fields.json` | Что записывается в определения: `{название: [тактика, основная техника, все техники]}` |
| `import-mitre.js` | Записывает поля в определения Graylog (см. ниже) |
| `graylog-coverage.layer.json` | Слой для ATT&CK Navigator: число определений на технику |
| `attack-coverage.html` | Самостоятельная страница с матрицей и подсветкой покрытия, открывается в браузере |

Из 89 определений к технике привязаны 68, всего 52 разные техники. Остальные 21 (контейнерные
«тишина» и ошибки, здоровье KDC, SELinux AVC, AirDrop, смена DNS) атак не описывают и без техники.
У 13 привязок в таблице стоит «низкая» уверенность: они приблизительные, их стоит перепроверять.

## Поля в событиях

Скрипт добавляет в `field_spec` каждого определения три поля со статическим шаблоном:

| Поле | Пример |
|---|---|
| `mitre_tactic` | `Privilege Escalation` |
| `mitre_technique` | `T1548.003 Sudo and Sudo Caching` (основная техника) |
| `mitre_techniques` | `T1070, T1070.003, T1685.006` (все) |

**Где искать.** Поля пользовательские, в событии они лежат во вложенном объекте `fields`, поэтому в
поиске и на дашбордах пишется `fields.mitre_technique`, а не `mitre_technique`. Первый вариант
находит события, второй не находит ничего. Поток: `All events` (`000000000000000000000002`).
Запрос «события только с привязкой»: `_exists_:fields.mitre_technique`.

**Старые события полей не получают.** Поля добавляются, когда определение создаёт событие. Всё, что
сработало до записи, останется без них.

**Встроенное поле.** У определений в Graylog 7.2.1 есть собственное поле `tactics_techniques`, оно
пустое. Публичного API для его заполнения в нашей установке не нашли (`/api/mitre/*` возвращает
404), поэтому используется `field_spec`.

## Как записать поля

1. Открыть Graylog в браузере (залогиниться), F12 → Console. Вставить `import-mitre.js` целиком,
   затем `const SPEC = {...};` с содержимым `mitre-fields.json`.
2. Пробный запуск ничего не записывает:

   ```js
   await importMitre(SPEC, {dryRun: true})
   ```

   Если Graylog открыт не с корня (`https://host/graylog/`), добавить `{base: '/graylog'}`.
3. Запись:

   ```js
   await importMitre(SPEC)
   ```

   Перед записью полные копии определений сохраняются в `localStorage` браузера (ключ
   `defs_backup_<дата>`). Определения находятся по названию, остальные поля не меняются.
4. Проверка. Дождаться срабатывания любого алерта и посмотреть событие: в нём должны быть три поля
   `mitre_*`. В лаборатории проверяли командой `sudo id`.

## Дашборд

В лаборатории создан дашборд «MITRE ATT&CK: активность по алертам» из четырёх виджетов: события по
тактикам и топ техник за 7 дней, динамика по тактикам за 30 дней, техники по хостам. Все запросы к
потоку `All events` с условием `_exists_:fields.mitre_technique`, группировка по
`fields.mitre_tactic`, `fields.mitre_technique`, `fields.host`.

## Слой для Navigator

В ATT&CK Navigator: Open Existing Layer → Upload from local → `graylog-coverage.layer.json`. Слой
помечает версию ATT&CK 20; если в вашей копии Navigator версия другая, он предложит обновить слой.
Цвет клетки зависит от числа определений на технику.
